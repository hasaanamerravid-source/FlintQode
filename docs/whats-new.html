What's new in FlintQode 1.5.2

Released 2026-11-27.

Fixed in this release

  • Markdown preview stops competing with typing. Parsing runs only while the preview is visible and waits 180 ms after the last edit. The previous render stays on screen while the new one is prepared.
  • Split views sync changed text only. A keystroke sends one small document change to the peer editor. Moving the cursor does no peer work, and the peer state is no longer replaced on every transaction.
  • Returning to a tab restores its problems. Recreated editors get a fresh diagnostics check, the git gutter waits for a pause before its first diff, and teardown skips writes when the text and cursor have not changed.
  • The status bar and shortcuts do less work. Unchanged cursor and zoom values are ignored, and key presses resolve through a cached shortcut map instead of scanning every binding.
  • Search and Explorer stay responsive on large projects. Search shows 200 hits at a time with a “More” control. Explorer lowercases each entry name once, then reuses that value for later filter changes.
  • Startup makes one existence check. Recent files and restored tabs are checked in a single native call, and the session is loaded once for both restore and crash recovery.
  • Superseded searches are cancelled. A newer query sends a generation token to the native scan, which stops before serializing results from the older query.
  • More native work runs off the main thread. File stats, existence checks, reads and writes, folder operations, settings, recent files, plugin listing and error logging use blocking worker threads. Text reads keep the existing 24 MB cap.

Changed

  • User-facing copy in the app, website, release notes and documentation now uses plain, specific descriptions. Translations were updated to match, including the update strings that were still in English.
  • The About dialog lists the current renderer stack. The welcome and settings text no longer claims that update checks are disabled; checks stay opt-in in Settings.

Verification

  • New regression tests cover the preview scheduler, split sync, status no-ops, diagnostics after tab switches, the git gutter delay, search result limits, Explorer filtering, startup batching and native threading. The full frontend gate and Rust checks pass.
