System fit

Requirements & resource use

What the installed app needs, how much space the installers take, and the built-in guards that keep editing predictable on large files.

🖥️

Uses your system webview

FlintQode is built with Tauri 2. It uses WebView2 on Windows, WebKitGTK on Linux and WKWebView on macOS instead of shipping another Chromium runtime.

📦

No runtime to install

Node.js, Rust, Java and a C++ runtime are needed only to build from source. The installed app runs without them.

🔌

Offline by default

Editing, search, Git and the terminal work offline. An internet connection is only needed for updates, downloads and optional language servers.

Runtime requirements

What your machine needs

Pick the installer for your platform from the Downloads page. Package dependencies are handled by your package manager where applicable.

Platform Installers What must be present
Windows .exe, .msi 64-bit Windows 10 or 11 and the WebView2 Runtime (normally already installed with current Edge/Windows updates).
Linux .deb, .AppImage, .rpm 64-bit distribution with WebKitGTK 4.1 and GTK 3. The AppImage is portable, but still uses the system webview libraries.
macOS .dmg, .app.tar.gz Apple silicon build on a current macOS release. The webview is provided by WKWebView; the first launch may need the usual “Open Anyway” step because the build is unsigned.
From source Git repository Node.js 22.12+, Rust stable and the platform build tools. See the build requirements.

Leave additional disk space for your projects, terminal sessions and any language servers you install. Language servers such as rust-analyzer or pyright have their own requirements and are optional.

While you work

How resource use is kept in check

FlintQode protects large files from expensive work and keeps editor updates inside a single 60 Hz frame on a 10,000-line test document.

File size What changes
Above 24 MBOnly the first 24 MB is read and the tab is marked as truncated.
Above 4 MBThe tab becomes read-only, syntax highlighting is switched off and the content is no longer copied into the store on every keystroke.
Above 2 MBThe content is not written back into the store while typing.
Above 1.5 M charactersThe syntax tree is skipped; cheap checks such as whitespace and end-of-file still run.
Above 1 MBThe document is not sent to a language server.
⚡

Editor work stays under a frame

On a 10,000-line, 856 KB fixture, the DOM update p95 was 7.2 ms while typing and 8.0 ms with highlight-all active. The next-frame paint p95 was 18.9 ms and 22.7 ms, limited by the frame interval rather than editor work. These are browser measurements, not clean-VM native benchmarks.

🌙

Power save and low memory

Power save mode reduces glass, gradients, shadows, animations and background polling. Low memory mode removes the minimap. Line-length diagnostics are optional and off by default.

🧭

Terminals are bounded

Terminal sessions stay alive when the panel is hidden; set terminal.closeOnPanelHide to close them instead. Closing a tab ends only that shell, and app exit stops every PTY.

Measured resource use

Real numbers from the Linux app

The actual v1.5.0 AppImage was opened on a 4-logical-CPU Intel Core i3-2350M with X11 and WebKitGTK 4.1. Each figure is a 12-second sample of the whole FlintQode process tree, including the Rust shell, WebKit network helper and WebKit web process.

Scenario CPU RSS PSS Private
Idle, settled window5.8–6.2% of one core (about 1.5% of this 4-CPU machine)~459 MiB~299 MiB~217 MiB
Continuous typing, ~60–70 keys/second158% of one core (about 40% of this machine)476 MiB332 MiB255 MiB
Idle again after typing5.8% of one core484 MiB338 MiB262 MiB

At idle, the Rust process used about 2.7% of one core with 129 MiB RSS / 72 MiB PSS, the network helper used 0% with 48 MiB RSS / 22 MiB PSS, and the WebKit web process used about 3.1–3.4% with 274–306 MiB RSS / 205–252 MiB PSS. During typing, the web process accounted for roughly 129% of one core. The whole tree held 55–62 threads and 107 file descriptors. RSS counts all mapped pages; PSS shares them between processes; private memory is what is charged only to FlintQode.

Method: CPU was derived from utime/stime deltas in /proc/<pid>/stat over 12 seconds; memory came from stat and smaps_rollup. This is one Linux machine, not a Windows/macOS or clean-VM benchmark. Your numbers will change with the project, open terminals, language servers, extensions, GPU and OS.

Check it yourself

Use Task Manager on Windows, Activity Monitor on macOS, or ps/System Monitor on Linux. Compare the editor with one empty tab, then with a real project open. Remember that webview memory may be counted as shared rather than charged entirely to FlintQode.
