Frequently asked questions

Common questions about installing, using and building FlintQode.

What is FlintQode? ▾
FlintQode is a lightweight, native desktop editor for code, Markdown and plain text. It is built with Tauri 2 (a small Rust backend plus your system's webview) and a React + CodeMirror 6 interface. It avoids the Electron bloat of shipping a whole Chromium runtime.
Which platforms are supported? ▾
Windows (.exe, .msi), Linux (.deb, .AppImage, .rpm) and macOS. The interface is identical on every platform because the window frame is drawn by the application itself.
Is it really not Electron? ▾
Correct. The first FlintQode releases were Electron, but FlintQode 2 replaced Electron with Tauri 2. The renderer stays React + CodeMirror 6, while the native layer is Rust. There is no Node.js runtime in the webview.
How do I install on Linux? ▾
Download the .deb (Debian/Ubuntu), .rpm (Fedora/openSUSE) or .AppImage (any distro) from the Downloads page or the GitHub release. For .deb/.rpm use your package manager; for .AppImage, mark it executable and run it.
Can I build from source? ▾
Yes. You need Node.js 20+, Rust stable, and (on Linux) WebKitGTK 4.1 and GTK 3 dev packages. Then run npm install && npm run build:app.
Does it support language servers? ▾
Yes. FlintQode hosts LSP servers (clangd, pyright, tsserver, gopls, rust-analyzer and more) natively in the Rust backend and shows diagnostics, go-to-definition and find-references in the editor.
Is there a plugin system? ▾
Yes. Plugins are JavaScript files placed in the plugins folder of your user-data directory. They can register commands, read the editor, show toasts and use the window.api bridge.
Where are settings stored? ▾
In the platform application-data folder: %APPDATA%\dev.flintqode.app on Windows, ~/Library/Application Support/dev.flintqode.app on macOS, and ~/.local/share/dev.flintqode.app on Linux.
